# #62 导入原型评审规格

## 目标

交付单元的原型页可以导入图片、PDF 和静态 HTML，供团队在线预览和画线批注。原型页展示文件名、导入角色、导入时间和「只读 · 导入」。

## 方案选择

- **只读评审原型（已选择）**。导入记录归属当前单元。评审者可以选择历史导入并查看该份文件的批注。正式制品树继续引用现有原型版本。
- **正式原型版本**。导入会推进 `proto` 版本，并影响 AD 的衍生引用、方案审批和构建。需要单独定义导入文件作为构建输入的契约。

## 数据与权限

- 首期支持 PNG、JPEG、未加密的 PDF 和 UTF-8 编码的静态 HTML。单文件上限 20 MiB，超限返回 413。格式或文件内容不合格时，返回可读错误，账本没有导入事实。上传绑定单元登记序号，登记已更换时返回 409。
- 原件通过现有内容寻址仓库存储。导入事实记录 digest、文件名、媒体类型、字节数、可验证的尺寸，以及会话角色和导入时间。账本序号标识一次导入，同一文件重复上传时也能区分批注。
- 导入和画线沿用原型评审的 `acceptProto` 权限，由 PA 执行。可查看当前单元的角色可以预览。会话目前提供角色，导入来源显示为「PA 产品」。
- 批注使用对应预览的实际边界：图片的整个画面、PDF 渲染后的首页、HTML 固定视口下可滚动的文档。左上角为原点，画线将两端的横纵比例（0–1）保留六位小数落账。批注使用现有 `annotation.added` 事实，带所属导入序号。原来的框选批注继续按原格式回放。
- PDF 使用只读画布预览。静态 HTML 使用固定视口和沙箱，保留内联样式和内嵌资源。长页面可滚动查看文档顶部最多 8192 像素。脚本、交互表单和外部资源请求由沙箱及内容安全策略限制。导入原型提供画线及查看批注入口，覆盖层随预览区域缩放。
- 导入记录服务于评审。质量报告缺少视觉比对证据时仍显示「判不了」。

## 验收

上传 PNG、JPEG、PDF 和 HTML，分别验证预览、来源、只读标识和角色权限。HTML 验证正文及内联样式可见，脚本和外部请求被阻止。画线保存后刷新并调整窗口尺寸，位置和内容保持一致，历史导入的批注按序号区分。检查 `/api/state?pbc=<单元>` 中的 `annos`，并核对落账的事实类型和坐标。验证超限、错误格式和越权请求没有导入事实，质量报告保持当前判定。最后跑五套已有本地回归。
