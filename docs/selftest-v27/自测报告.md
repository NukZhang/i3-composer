# **附：本轮修复说明（验收暴露的缺陷）**

| 缺陷 | 现象 | 修法 | 验证 |
|---|---|---|---|
| pubsub 投到别的端口 | 换个端口起实例（如 8090）时工作流照跑、事件一条也收不到；验收只会报「收到 0 条」，看不出根因 | 启动读 sidecar `/v1.0/metadata`，与本实例监听端口比对：不一致打 WARN，并写进 `/api/health` 的 `pubsub` 字段；两套验收加「投递地址一致」断言 | 8091 实例实测 `ok=false` 且 detail 写明两个端口（`logs/pubsub-wiring-check.log`）；8080 实例 `ok=true` |
| 工作空间随机 id 撞号 | `newID("w")` 生成后不查重，撞号会让两个工作空间静默共用一条记录 | 与项目共用 `uniqueID`：撞了依次退 `base0`、`base1`…… | 新增单测 `TestUniqueID`（含连续撞号） |
| 验收脚本截错页面 | 「加入已有」后当前项目切到了别人的项目，闸门截图点不到本项目单元，截出来是别的页面 | `acceptance_v27.cjs` 在截闸门前先点回本项目；闸门截图并入主流程（第 16–18 张） | 重跑后 16–18 三张均为三种单元的真实闸门 |
